# Implementation Plan

## Task Overview
本実装計画は、Luhnアルゴリズム学習・検証SPAを段階的に構築するためのタスクを定義する。プロジェクトセットアップから始まり、コアロジック、UI統合、テストの順で進める。

## Tasks

- [x] 1. プロジェクトのセットアップと基盤構築
- [x] 1.1 (P) Vite + TypeScript + Tailwind CSSプロジェクトを初期化
  - `npm create vite@latest`でTypeScriptテンプレートを選択
  - Tailwind CSS 4.0をインストール(`npm install -D tailwindcss postcss autoprefixer`)
  - `vite.config.ts`に`@tailwindcss/vite`プラグインを追加
  - `tsconfig.json`でTypeScript設定(noImplicitAny: true, strict: false)を構成
  - プロジェクト構造(src/, index.html)を確認
  - _Requirements: 4.1, 4.3, 4.4, 5.1_

- [x] 1.2 (P) 基本的なHTMLページ構造を作成
  - index.htmlにLuhnアルゴリズム解説用のセクションを配置
  - Tailwind CSSのユーティリティクラスで基本的なレイアウトを構築
  - 固定配置フォーム用のコンテナ要素をマークアップ(デスクトップ: 右上、モバイル: 下部)
  - レスポンシブブレークポイント(sm:, md:, lg:)を使用
  - main.tsをモジュールスクリプトとして読み込み
  - _Requirements: 1.4, 3.1, 5.1, 5.2_

- [x] 2. Luhnアルゴリズムの実装
- [x] 2.1 (P) Luhnアルゴリズムの型定義を作成
  - ValidationResult型を定義(isValid: boolean, message: string)
  - LuhnService型を定義(validateLuhn, calculateChecksum)
  - 型をエクスポートして他モジュールから利用可能にする
  - _Requirements: 4.2_

- [x] 2.2 Luhnアルゴリズムの検証ロジックを実装
  - 文字列を数値配列に変換する関数を実装
  - Luhnチェックサムを計算する関数(calculateChecksum)を実装
  - 右から左に桁を処理し、2倍にする桁を決定
  - 2倍した結果が10以上の場合は各桁を合計
  - 全桁の合計が10で割り切れるかを判定
  - validateLuhn関数でValidationResultを返す
  - _Requirements: 2.1, 2.2, 4.1_

- [x]* 2.3 Luhnアルゴリズムのユニットテストを作成
  - 有効な数値(例: クレジットカード番号)のテストケース
  - 無効な数値のテストケース
  - エッジケース(1桁、空文字列)のテストケース
  - calculateChecksum関数の既知のチェックサム値検証
  - _Requirements: 2.2_

- [x] 3. バリデーターUIロジックの実装
- [x] 3.1 入力バリデーション機能を実装
  - 入力値が空文字かチェックし、適切なメッセージを返す
  - 正規表現`/^\d+$/`で数値のみかチェック
  - 非数値入力時のエラーメッセージを返す
  - ValidationResult型を使用してエラー情報を構造化
  - _Requirements: 2.4_

- [x] 3.2 リアルタイム検証のイベント処理を実装
  - setupValidator関数を作成し、DOM要素をパラメータで受け取る
  - 入力フォームにinputイベントリスナーを登録
  - イベント発火時に入力値を取得してバリデーション実行
  - バリデーション結果をluhn.tsのvalidateLuhn関数に渡す
  - 結果をUIに反映(有効/無効/エラー)
  - _Requirements: 2.2, 2.3, 3.2_

- [x] 3.3 検証結果のUI更新機能を実装
  - 結果表示用DOM要素を取得
  - ValidationResultのisValidに基づいて表示を切り替え
  - 有効な場合は成功メッセージとスタイルを適用
  - 無効な場合はエラーメッセージとスタイルを適用
  - textContentを使用してXSS対策を確保
  - _Requirements: 2.3, 2.4_

- [x] 4. Luhnアルゴリズム解説コンテンツの作成
- [x] 4.1 (P) Luhnアルゴリズムの概要説明を記述
  - アルゴリズムの目的と用途を簡潔に説明
  - クレジットカード番号、IMEI番号などの実用例を紹介
  - HTMLのセマンティック要素(section, h2, p)を使用
  - Tailwind CSSで読みやすいタイポグラフィを適用
  - _Requirements: 1.1, 1.3_

- [x] 4.2 (P) Luhnアルゴリズムの計算手順を段階的に説明
  - ステップバイステップの計算プロセスを記述
  - 具体的な数値例を使って各ステップを説明
  - 視覚的に理解しやすいレイアウト(ol, code)を使用
  - Tailwind CSSでセクション間の余白とスタイルを調整
  - _Requirements: 1.2_

- [x] 5. アプリケーション統合とスタイリング
- [x] 5.1 main.tsでアプリケーションを初期化
  - DOMContentLoadedイベントリスナーを登録
  - DOM要素(入力フォーム、結果表示)を取得
  - setupValidator関数を呼び出してバリデーターを初期化
  - DOM要素が存在しない場合のエラーハンドリング
  - コンソールエラーログを出力
  - _Requirements: 5.1, 5.2, 5.3_

- [x] 5.2 固定配置フォームのスタイリングを完成
  - デスクトップ用の固定配置スタイル(fixed top-4 right-4)を適用
  - シャドウとパディング(shadow-lg p-6 rounded-lg)で浮遊感を演出
  - モバイル用のレスポンシブスタイル(fixed bottom-0 w-full)を適用
  - z-indexを調整して解説コンテンツとの重なりを防止
  - アクセシビリティを確保(フォーカス可能、コントラスト比)
  - _Requirements: 3.1, 3.2, 3.3_

- [x] 5.3 解説コンテンツの最終的なレイアウト調整
  - 解説セクションと検証フォームの共存を確認
  - 固定フォームが解説コンテンツを隠さないようパディングを調整
  - スクロール時にフォームが追随することを確認
  - モバイルとデスクトップの両方でレイアウトをテスト
  - _Requirements: 1.4, 3.3, 5.3_

- [x] 6. ビルドと動作検証
- [x] 6.1 開発サーバーで動作を確認
  - `npm run dev`で開発サーバーを起動
  - ブラウザでアプリケーションを開く
  - 有効な数値を入力して「有効」表示を確認
  - 無効な数値を入力して「無効」表示を確認
  - 非数値入力でエラーメッセージを確認
  - スクロール時にフォームが追随することを確認
  - _Requirements: 2.2, 2.3, 2.4, 3.2_

- [x] 6.2 本番ビルドとバンドルサイズを検証
  - `npm run build`で本番ビルドを実行
  - dist/フォルダにビルド成果物が生成されることを確認
  - ビルド分析でバンドルサイズを確認(目標: < 100KB)
  - `npm run preview`でビルド済みアプリケーションをプレビュー
  - 本番環境で動作を確認
  - _Requirements: 4.3, 4.4, 5.1_

## Implementation Notes

### Parallel Execution
`(P)`マークが付いたタスクは並列実行可能。以下のタスクは独立して実施できる:
- 1.1: プロジェクトセットアップ
- 1.2: HTMLページ構造作成
- 2.1: 型定義
- 4.1, 4.2: 解説コンテンツ作成

### Sequential Dependencies
以下のタスクは順次実行が必要:
- 2.2 → 3.2: Luhnロジック実装後にバリデーターが依存
- 3.2 → 3.3: イベント処理実装後にUI更新が依存
- 5.1: すべてのモジュール実装完了後に統合

### Optional Tasks
- 2.3: ユニットテストは実装完了後に追加可能。MVP配信を優先する場合は遅延可能
